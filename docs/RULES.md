# RULES — Правила совместной разработки

> Регламент распределения ролей между моделями, порядок выполнения задач и арт-пайплайн. Без бюрократии.

---

## 1. Схема взаимодействия по этапам

Для каждого этапа создается **отдельный чат**:
1. В новом чате работает **Claude Opus**: анализирует код и `docs/STAGES.md`, формирует архитектурный план этапа.
2. В плане выделяется блок **«ТЗ на генерацию моделей и ассетов»** для пользователя (если это необходимо).
3. **Пользователь** отдельно генерирует модели/спрайты по ТЗ (внешними инструментами, в браузере и т.д.), складывает их в указанные в плане папки с точными именами, и только после этого нажимает кнопку **«Proceed»** на интерактивном артефакте плана.
4. Переключаемся на **Gemini Flash**: исполнитель подхватывает готовый утвержденный план, берёт уже готовые файлы из указанных папок и реализует код строго по шагам.

---

## 2. [РЕЖИМ ПЛАНИРОВАНИЯ — Claude Opus]

1. **Анализ:** По команде «Составь план для этапа N» анализируй `docs/STAGES.md`, `docs/STATE.md` и кодовую базу (используй `graphify query` и `context-mode search` для исследования архитектуры без раздувания контекста).
2. **Формат:** Формируй план **ВСЕГДА** в виде интерактивного Артефакта с параметром `RequestFeedback: true` (для появления кнопки «Proceed»).
3. **Содержание плана:**
   * Архитектура изменений (структура классов, сигналов, Mermaid-диаграммы).
   * Список создаваемых и изменяемых файлов проекта.
   * **Блок арт-задач для пользователя (до нажатия Proceed):**
     * Список требуемых моделей/спрайтов.
     * Точный путь и имя файла для каждого ассета (например: `assets/sprites/buildings/fusion_reactor.png`).
     * Изометрические требования: габариты (1×1, 2×2, 3×3), угол 30°, прозрачный фон.
     * Визуальное описание / готовый промпт для генератора (как модель выглядит, материалы, палитра, подсветка).
   * Пошаговый план реализации логики для Gemini Flash.
   * Критерии приемки и список автоматических тестов.

---

## 3. [ДЕЙСТВИЯ ПОЛЬЗОВАТЕЛЯ ПО АРТ-ПАЙПЛАЙНУ]

* Модели и графика генерируются **НЕ** на лету агентом в кодовом чате, а пользователем отдельно.
* Пользователь берет промпты и требования из блока артефакта, генерирует изображения/модели, размещает их в обозначенные папки проекта.
* После размещения ассетов пользователь нажимает кнопку **«Proceed»** в артефакте.

---

## 4. [РЕЖИМ ИСПОЛНЕНИЯ — Gemini Flash]

1. **Старт:** После нажатия «Proceed» берешь задачи из артефакта и исполняешь строго по шагам. Ассеты уже находятся по путям, зафиксированным в плане.
2. **Правило контекста и субагентов:**  
   * **Запрещено** засорять основной чат чтением десятков файлов или массовым поиском по коду.
   * Для навигации по архитектуре и графу зависимостей используй `graphify query "<вопрос>"` или `graphify-out/GRAPH_REPORT.md`.
   * Для быстрого полнотекстового поиска без расхода контекста используй `context-mode search "<запрос>"`.
   * Если нужно провести масштабное глубокое исследование — запускай `research`-субагента и возвращай в чат только выжимку.
   * После модификации файлов обнови граф (`graphify update .`) и индекс (`context-mode index .`).
3. **3D и ассеты:**  
   * Используй инструменты, скрипты и пути из `docs/TOOLS.md` и утвержденного плана.
   * Никакой генерации мешей текстом в коде.
   * При необходимости вызови команду обновления кэша импорта Godot.
4. **Финал этапа:**  
   * Прогони регрессионные тесты через `tests/test_runner.tscn` (Exit code 0).
   * По завершении обнови статус этапа в `docs/STATE.md`.
